# 每周 Skill 清理、整理、打包与归类

修订：WEEKLY-MAINTENANCE-20261117-01。适用影视分镜、漫画分镜、视觉资产三套 Skill 及其学习成果。用户于2026-11-17明确要求使用定时任务进行每周维护，并把任务写入 Skill。

## 调度与边界

- 默认北京时间每周日早上08:00左右执行，弹性窗口约前后一小时；首次2026-11-22。持续至用户暂停或调整。
- 独立维护任务已获本次授权；旧“不另建学习任务”不阻止此维护任务。每日学习、周五审核、周六备份和月底专项清理保持，不能重复启动学习或另建其他任务。
- 自动流框架独立维护：不写入 workflows/ 下任何文件，不随 Skill 升版改写或升级框架，不自动新增心得案例。现有已授权实践只可维护索引定位；新经验留待用户实际使用后专项处理。
- 维护只整理实际已保存的内容，不补跑学习、不生成媒体、不新增查询额度，不改技巧三票、信用及原始评价。
- 以 GitHub main 为唯一可信源。普通制作仍按问题检索，不自动加载维护正文。维护入口是第0层，本文件是直接第1层；不递归展开本文件提到的规则。
- 执行配置保存于 registry/weekly-maintenance-task.json，完整任务指令保存于 registry/weekly-maintenance-prompt.txt。配置是任务定义；实际启用/下次运行以调度服务回读为准，写配置不等于已创建定时任务。

## 1. 固定基线与防重

1. 按 Asia/Shanghai 当地日期与 ISO 周生成 YYYY-Www 周标识。读取 registry/maintenance/YYYY-Www.json；首次不存在则新建最小运行记录。
2. 记录 source_commit、run_id、状态和最近成功基线。completed 且相同源提交时返回已有成果；已有运行占用时不抢占。中断恢复只续做未完成步骤，不重复发布或重打已核验同内容包。
3. 改动前固定 main 提交，创建并回读备份分支，核对相关文件路径和 Git blob SHA。保留可恢复快照，检查后再动手。
4. 首次处理近7个北京时间自然日的已保存成果及轻量未决索引。后续用最近成功基线到当前提交的差异发现漏项；旧未决正文只在本次具体命中时定向读取，不遍历历史账本或重跑学习。
5. 并发学习/维护写入时核对最新 main，重新审查差异和冲突，不覆盖并发内容，不强推。无法完整核验就标 partial/blocked。

## 2. 清理与整理

- 每条新增内容先与已有知识对照，注明新增、补充、重复、冲突或过期；没有新结论只保留案例证据，不重复造规则。
- 删除重复的派生索引项，清理可再生成的临时文件；源正文合并时保留出处、差异、适用边界和原文追溯。
- 已被替代或过期的内容退出日常推荐，保留状态、原因和替代指针；冲突标注待验证，不自行判定方法有效。
- 每周默认非破坏性清理：不永久删除原始学习记录、失败案例、历史、认可证据、未决候选或未解决问题，不批量清库。候选已合并PR、日期久或用户未回复都不等于已关闭。
- 月底既有清理另按明确最终决定和恢复证据处理，本任务不自动放宽删除条件。45条已知历史缺口继续标历史归档，不恢复、不造占位。
- 不把旧 global-state 或私人对话、内部标识、无关素材复制为公开发布载荷。

## 3. 归类与快速检索

- 一级沿用影视分镜、漫画分镜、视觉资产；已有自动流实践只作为只读检索引用，不纳入批量写入；主题可多标签，包括提示词、风格审美、叙事/镜头、动作、表演、资产、观影案例、GitHub探索等，实际有内容才建类。
- 每项至少有稳定ID、简明用途、适用条件/限制、来源、正文路径、验证状态和关键词。按现有 catalog schema 保存；口语检索词用 aliases，来源和详证留正文/案例记录，不复制全文到索引。
- 共用知识只保留一份权威正文，多标签引用；媒介差异各自保留。案例认可、辅助测试和静态校验不等于通用技巧 active。
- 更新 knowledge/catalog.json，必要时更新分类/别名，重建 knowledge/views、knowledge/library-map.md 与 registry/library-inventory.json。正式规则和案例不因七天窗口失效；候选只在学习/维护/回查模式可见。
- 回答实际使用问题时先返回短摘要、状态、路径，再定向读命中正文。无命中可扩词，不编造答案或全库加载。

## 4. 校验与发布

- 至少实测5条自然语言查询，覆盖本周新增、旧有效案例、候选隔离、失败限制和常用口语。记录 query、mode、skills、命中ID/路径与结论；无新增时用现有真实条目，不造新内容。
- 核对新旧路径可达、正文哈希、重复ID、来源和状态；检索命中不代表方法已验证。
- 按现行版本政策：实际执行内容变化只升受影响 Skill 的修订号；纯回执不空升版，核心能力升版保持原审批条件。
- 源内容与版本更改后运行 tools/refresh_release_manifest.py，再运行 tools/verify_repository.py 及相关测试，检查真实差异。
- 完成固定基线→备份核验→带版本号PR→检查→按授权合并→独立main逐文件回读。未合并只称待发布；校验/回读失败不得宣布生效。

## 5. 打包与周报

- 使用最终已核验固定提交制作 skill-weekly-YYYY-Www.zip；包括本周摘要、快速使用说明、分类检索索引、实际新增/更新内容和必要依赖、来源/状态表、三套版本、源提交及逐文件SHA-256清单。
- 已验证、候选和失败材料明确分区/标注，保留引用和适用限制。必要依赖缺失时记录缺口，不把不可独立使用的包标成可用。
- 同时提供该固定提交的完整源码ZIP恢复链接；周包用于快速复用，完整源码包用于恢复。不要把ZIP反复提交到源码仓库。
- 实际打开周包，核对文件清单、可读取性和每个SHA-256；保存为可持续访问的文件并返回下载链接。只在保存与校验均成功后称“打包完成”。
- 周回执记录 week、source_commit、published_commit、backup_ref、versions、counts、retrieval_checks、validation、package_sha256、completed_steps、remaining、status。公开回执只含仓库范围事实，不发布私有下载令牌、对话标识或私人存储标识；下载链接交给用户。
- 周报用中文说明清理了什么、归入哪里、新增/保留/待验证内容、至少5条实际检索示例、发布与校验结果、包下载和阻塞项。无新增仍检查索引和恢复包，不凑数量、不空升版本。
- 本规则安装完成不等于首周维护或打包已经执行；以真实运行回执和可打开成果验收。
