# 按剧情变化调度制作方法

修订：PRODUCTION-FOUNDATION-20261111-01。适用：已解析的故事、视频改编与相关资产规划。此规则组织现有方法，不授予候选有效性或生成能力的新认证。

## 先明确本次输出

区分理解分析、制作规划、正式交付；区分影视、漫画、基础资产、宣传设计与动态用途图片。用户只要分析时不自动生成媒体或完整提示词。已有风格与项目设定沿用，缺失且影响正式交付时才询问；实际视频制作继续执行当前模型、输入、时长与风格核验。

## 每次调度的顺序

1. 固定已校验仓库版本和项目原文/解析版本；通过短目录定位，不每次全库重读。读取当前场的目标、节拍、前后状态和必要伏笔，确认局部判断来自原文。
2. 用模式、媒介、任务阶段、状态及适用条件排除不能使用的条目。必读、检索命中、直接按 ID 读取和补检使用同一资格检查。未知状态或失效必需规则明确报缺口；候选、案例和历史指令不得冒充正式规则。
3. 对每个节拍选主要表达问题，再选主方法和必要辅方法。动作、关系、情绪、喜剧、悬念可以交替或共存，但不能把所有风格同时堆叠。爱情表达须有关系证据；游戏化/ACT须有风格许可。技术上可用不等于当前叙事合适。
4. 先读取 required_rules 与 read_plan_ids 对应的完整语义单元及限制。optional_evidence_ids 是可选案例，只在具体比较需要时读取；不要为了“全面”把所有案例加入上下文。全片一致性规则复用，局部方法随节拍调整。
5. 记录选择理由、依据的源段落、采用的知识 ID、未采用的相关方法及原因。找不到方法时在明确范围内补检一次；仍不足就报告缺口或采用已有保守处理，不能无界搜索或强塞不相关内容。
6. 按当前阶段产出结果，复查原文忠实度、人物与物件状态、动作因果、观众获知顺序、局部情绪过渡、风格一致性及交付完整性。已知缺陷先修；需要用户事实确认时只暂停依赖部分。

## 保持变化与连续性

整体基调限定风格边界，局部节拍决定当下表达强度与节奏。打斗停止、身份揭示、关系缓和或喜剧插入时，重新检查主要表达问题；不要继续机械套用上一拍的高速、震动或低沉气氛。

跨拍交接至少核对人物位置、朝向、伤势、持物、空间锚点、时间及信息状态。不同人的情绪分别追踪，不能用一个全场标签覆盖。表演与摄影是创作建议，原文事实和用户已确认设定是约束，两者分别记录。

信息揭示先解决事件因果和观众获知顺序；只有实际存在悬念或威胁时才选择悬疑/威慑方法，心理释然、坦白和安抚不自动压暗或营造恐惧。

情绪标签不直接规定景别、色温、运镜或音乐。选择必须说明该手段帮助观众读到哪项变化，且符合既有风格与声音边界。只有关键词的自动分类只能作为候选提示，未经语义复核不能直接驱动制作。

## 与学习底层逻辑的接口

学习、研究新方法与方法发布完整执行既有七问、来源独立性、复现和人类确认。日常制作按本次风险做相应检查，向用户说明影响结果的结论，不每个镜头预读整套学习审计正文。

项目试用证明的范围仅限实际观察；文字路由检查不能证明成片更好。真实剧本的角色、剧情、风格和偏好不变成通用默认知识。发现普遍方法的新主张时进入既有候选流程，不在制作中直接转正或改积分。

## 工具与无工具路径

有执行环境：先 query_knowledge 获取短结果及 read_plan_ids，再 read_knowledge 定向读取；需要结构化剧本时使用 script_workspace 提取结构、由阅读者补充 analysis，再运行 validate 与 route_production。结构提取工具不自动理解剧情。

已读回执只在相同任务且正文仍保留于当前上下文时复用；换会话或压缩后丢失正文时使用新回执文件重新读取。已校验文件快照可以跨会话复用，但它不证明模型当前仍持有正文。

无执行环境：读取当前任务的 knowledge/views 短目录，按同样资格和阶段筛选，读取入口直接声明的正文及必要段落。无法核实远端版本或内容哈希时说明未核实范围，不能宣称已完成自动校验。保留项目阅读覆盖、原文定位和更新记录。
