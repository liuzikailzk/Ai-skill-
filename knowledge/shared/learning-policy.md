## 3. 证据、独立性、时效与快照

## 4. 状态机与三票门槛
审计单元是有边界的技巧／修订条目，不能把整个Skill包的一个通过条目当作全包通过。

| 状态 | 条件与使用方式 |
|---|---|
| candidate | 值得验证或历史待审；证据／复现不足，不能作为正式默认方法 |
| observing | 三轮已完成、证据票和复现票均通过，等待有效人类票 |
| conflicted | 有明确反证或未解决来源冲突；不得active |
| active | 周五审计中用户明确确认，三票有效、回测通过、无冻结或熔断、已发布并回读核验 |
| deprecated | 过期、被替代或被证伪；保留原因、替代方案、最后验证日期 |
| rolled_back | 新版失败，保留失败证据和恢复目标、理由、差异及回测记录 |

candidate通过两张技术票后→observing；任一阶段发现未解决反证→conflicted；observing经周五人类票和发布门槛→active；active可降级为conflicted／deprecated或失败回滚。冲突消除后重新验证票据，不直接恢复active。没有人类票最多observing或conflicted；连证据／复现票也没过就留candidate，不能把“等用户跑视频”标observing。

- 证据票：最低来源组合、独立性、反证留痕全部满足，无致命反证。
- 复现票：具体环境／模型版本／入口、材料及其校验值、步骤、参数／完整提示词／种子、预期、实际输出与检查结果、失败条件均有记录。平台不暴露种子时明确“不提供”及随机性限制，不编种子。缺环境或实际结果就不通过；图片自检不代替视频复现，静态样例不证明动态技巧有效。
- 人类票：用户对具体条目和版本的明确确认，记录时间、原话定位、范围、是否撤销；周五集中征集，不把沉默、夸奖、使用某作品或授权维护当转正。人类票最终决定，但不能代替失败的技术票或解除熔断。明确改制度须另留治理修订，不伪造既有票。
- 非active草案存references/audit/candidates/，正式流程不得自动注入。用户明确要求试用时才在隔离测试副本使用并标试验，不改已确认项目。旧内容迁移为candidate且标origin=legacy_unreviewed，不倒填证据或人类票；历史基线版本并不等于active认证。
