# 剧梦操作映射：与软件无关的流程怎样落地

本页是框架到剧梦的操作映射，只承接影视、资产 Skill 已准备的创作输入。它不承担剧情、风格或镜头设计；仅依据用户实际使用中的操作证据更新，不随创作 Skill 升版自动改写。

观察日期：2026-11-15至17。本页只记录当时实际操作；按钮、模型名称、单段时长、价格和导出行为可能变化，开工时重新核对。

| 通用能力 | 本次剧梦实现 | 复用前要检查 |
|---|---|---|
| 生成与查询 | 分镜提交后保留任务与历史版本 | 区分已提交、处理中、失败和已有视频；超时先查旧任务 |
| 从成片取参考 | 分镜历史“引用”→解析视频→选帧→“引用当前帧” | 等实际画面可选，再检查人物状态；不要把图像增强当成免费引用 |
| 向下一镜传递参考 | 将引用素材以完整标签插入提示词，再复制到另一分镜 | 保存重载后核对素材栏、标签及素材身份；普通文件名不等于绑定 |
| 保留场内人物 | 素材栏继续保留未离场角色与必要群像 | 正文没显示名字不代表素材缺失；反过来，也不能只看正文认定已绑定 |
| 管理结果版本 | 同一分镜保留原生成和补做历史，选择当前使用版 | 最新不自动最佳，记录真实选中任务 |
| 裁剪 | 时间线设置有效起止范围 | 下载源视频可能仍包含完整原片，交接另列裁点 |
| 平台推理 | 用户当时要求先完成流程，再按自己的创作依据重写 | 平台生成的提示词不自动成为创作权威；替换前保留必要原文和范围 |
| 视频输出 | 本轮使用九梦2.5 Pro、480P；曾支持最长30秒 | 历史观察不是未来能力或价格保证，风格词“4K”不改变480P设置 |

## 迁移到另一款软件

先分别检查：能否引用图片／视频；参考是全片影响还是只控制首帧；能否锁定人物身份；能否读回素材绑定；是否保存多次历史；能否按任务恢复；裁剪作用在时间线还是源文件；费用失败与退款怎样查询。

本项目“单独修改声音而保留画面”的能力尚未在这份案例中验证，不能据支持视频编辑就假定支持。任何只改对白用词的任务，要先确认配音替换、口型处理和画面保留范围，再选择操作。

没有等效能力时明确缺口，可调整分段或使用受支持的参考方式；先验证，不能直接把剧梦按钮流程换个名字继续执行。通用状态记录仍可沿用。
