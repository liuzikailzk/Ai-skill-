# 自动流框架：配合影视、资产 Skill 使用

> **防止误用：本区只负责底层编排，不能单独承担剧本解析、对标、风格、分镜或资产创作。** 执行前先看 [使用边界](AGENTS.md)。框架说明和案例不是付费生成授权，也不是现成的独立无人值守服务。

## 三者怎样配合

| 分工 | 负责 | 交接内容 |
|---|---|---|
| 自动流框架 | 组织步骤、调用、素材绑定、任务恢复、预算检查、连续性状态和交付 | 接收创作结果，编排执行并反馈实际结果 |
| 影视分镜 Skill | 剧情解析、对标、整体风格、镜头调度、分镜与动态提示词 | 剧情与镜头方案、逐镜输入、创作验收要求 |
| 资产 Skill | 人物、场景、道具、图像提示词及可动性检查 | 资产要求、可用参考、身份与状态信息 |

现有三套 Skill 保持原位、原职责；漫画任务按原漫画 Skill 处理，不能套用本区影视案例代替漫画创作规则。软件按钮和接口映射放在 `adapters/`，不写进创作 Skill。

## 独立维护，不连带升级

- GitHub 是读取来源。开工时分别记录框架修订和本次调用的影视、资产 Skill commit／版本；同一已批准批次保持记录的版本。
- 影视、资产 Skill 可以独立更新，其更新不会触发本区同步、改写、升版或案例重写；本区更新也不改三套 Skill 的正文、版本、账本或学习计划。共用仓库和检索目录不代表共用维护范围。
- 新任务可调用当次核验的创作 Skill。若其输出字段或要求已无法衔接，先报告接口差异并暂停受影响步骤；不静默修改框架、创作 Skill 或已批准输入。独立维护不等于承诺任意未来接口都兼容。
- 日常更新只来自用户实际使用：记录现象、证据、原因、处理、复检与限制。没有新实践不更新；不按日期、定时学习或网上新技巧自动改本区。框架职责和结构调整须由用户明确提出。

本区于2026-11-17建立，当前案例是项目进行中的阶段记录。局部认可、生成成功、连续性检查和完整音画终审分别记录；不自动转正技巧或认定全片验收。

## 仅在用户实际使用后补充

- 同一问题保存“现象→证据→已确认原因／推测→处理→复检结果→剩余限制”，保留失败；只写“已解决”无法帮助下次排错。
- 通用方法写在方法页；某个软件的名称、按钮、格式、限制写在适配页。更换软件时重新检查能力，不改写历史操作事实。
- 项目具体时长、画幅、风格、音色策略、报价与额度是项目参数，不直接变成所有项目的固定要求。
- 局部认可、实际生成成功、连续性检查和完整音画终审分别记录。方法记录不自动变成active技巧，也不自动登记信用奖励。
- 后续有新证据时追加日期与修正说明；不抹掉原失败和当时未解决的问题。完整剧本、账户信息及私有媒体不随阶段方法摘要上传。

本区没有新增自动运行、付费生成或历史预算复用权限。
