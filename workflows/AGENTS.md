# 自动流使用边界

本规则只约束 `workflows/`。定位：独立的底层编排框架，配合影视、资产 Skill 使用；不新增或替代创作 Skill。

1. **先分工。** 自动流接收用户任务和创作 Skill 的结果，处理依赖、输入输出、素材引用、状态、费用、恢复、检查与交接。剧情、对标、风格、镜头设计和资产设计交给对应 Skill；不得用案例模板代替其完整流程。
2. **调用不改写。** 从用户指定的 GitHub 来源核验并读取本次所需 Skill；最多一层必要直接引用。只记录调用来源和交接结果，不改三套 Skill 正文、版本、账本、案例或定时学习任务。框架与创作 Skill 的修订分别记录，不用一个版本号代替两者。
3. **更新不联动。** 创作 Skill 升版不触发本区写入或升级；本区经验更新也不触发创作 Skill 升版。每日学习、定时版本检查和普通批量维护不得写本区内容。目录与哈希索引可随已授权的本区变更更新，但它们不是经验来源或写入授权。
4. **只从实际使用积累。** 用户使用自动流后，按“现象→证据→原因／推测→处理→复检→剩余限制”更新心得、案例和已验证的操作映射；无新实践不写。只写受本次事实支持的范围；保留失败、日期与旧结论，不把一次成功推广为普遍规则。改变框架职责、结构或通用约束须有用户明确要求。
5. **发现不匹配就停在交接处。** 缺少创作 Skill、必要参考或可核验输出时，可说明缺口并做不依赖它的规划；不得冒充已调用、绕过创作检查或继续依赖性的生成。新 Skill 与旧接口不兼容时记录差异，待明确适配后继续，不静默改源规则。
6. **例子不是授权。** 历史模型、时长、预算、风格、人物与案例结果均不是默认项目参数；付费、重试和外部操作仍受本次用户授权约束。任务完成、抽帧或转写不代替连续播放、听审或质量终审。
7. **只公开必要摘要。** 通用编排经验放 `methods/`，项目实践放 `cases/`，软件操作映射放 `adapters/`；不上传完整私有剧本、Token、账号信息和私有媒体。本区规则是执行约束，不是操作系统权限隔离或已安装的独立自动运行程序。

8. **逐镜执行错题检查。** 每个制作批次先用已验证的工作流心得安排步骤，再由影视和资产 Skill 按原文完成镜头与素材设计。逐镜按[错题检查表](methods/shot-checks.json)匹配当前动作、人物关系和已知反馈，人工补漏；付费前核输入和必要的上游证据，生成后复核实际选用版。命中旧错记失败，证据不足记待验，两者均停止此依赖链。返工须重验原先正确项及前后真实剪接点。独立镜头按各自的授权和检查推进。
