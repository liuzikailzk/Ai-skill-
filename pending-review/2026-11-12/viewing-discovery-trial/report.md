## 2. 两个目标及适用性

### 电影片段：同一对象的第二次展示增加了什么信息？

来源：[Blender官方下载目录](https://download.blender.org/demo/movies/)中的[Caminandes: Gran Dillama](https://download.blender.org/demo/movies/caminandes_gran_dillama.mp4.zip)。片尾可见 Blender Institute Production 2013、导演 Pablo Vazquez。选择理由是原始媒体可读、片段短、适合观察视线和空间关系；不将它称为AI影片或获奖案例。

素材146.041667秒、1920×1080、24fps。先以18张稀疏抽帧定位，正式分析24–44秒的40张画面（2帧/秒）；时间标记为采样点近似值，不是逐帧测出的剪辑边界。没有听音轨，不评价音乐、音效、对白或精确动作节奏。

| 片段位置 | 实际画面依据 | 判断 |
|---|---|---|
| 24–28秒附近 | 角色全身与环境，栅栏已在背景出现 | 不能说后文才第一次出现栅栏 |
| 28–33.5秒附近 | 角色面部、眼神变化与转头 | 提供角色关注方向；兴趣属于结合后镜的解释 |
| 33.75–36.25秒采样点 | 单独展示植物 | 先让对象可辨认 |
| 36.75–39.25秒采样点 | 回到角色面部反应 | 把对象与角色关注相连 |
| 39.75–42.25秒采样点 | 再次看植物，画面拉远、栅栏进入前景 | 新信息是植物与障碍的空间关系，不只是再次展示同一物件 |

可迁移到文字镜头规划的一个提醒：**回到同一对象时，检查是否补充了观众需要的新信息**。例如第一次看清想要的东西，第二次补上距离、门或阻挡。不是所有反打都必须新增信息，重复可以另有情绪用途。

这与现有 `film-core` 的“观众获知顺序／先建立空间／特写推动剧情”重合，因此保留具体观摩记录，不新增一条通用技巧。未做有无该镜头的理解度对照，不宣称观众理解更快或生成效果更稳定。

## 4. 实际复现、失败与重试

先运行外部辅助脚本 `--help`，实际尝试启动浏览器两次：默认Playwright浏览器文件缺失；使用环境中已有的 `/usr/bin/chromium` 后遇到 `socket() failed: Operation not permitted`。到此停止，没有绕过环境限制，也没有把脚本能启动服务器算成业务用例通过。原始启动命令使用headless模式。

随后隔离验证 `with_server.py` 的服务器生命周期，Python3.12.14、Playwright包1.62.0。测试脚本和结果在本目录，外部辅助脚本不复制入本仓库，取固定提交与`sources.json`中的blob指纹复现。

| 小测试 | 预期 | 实际 |
|---|---|---|
| 启动服务器后请求模拟表单，子命令正常结束 | 返回0，结束后端口关闭 | 返回0、端口关闭，通过 |
| 子命令主动返回7 | 原样返回7，仍清理服务器 | 返回7、端口关闭，通过 |
| 故意等待未启动的端口，超时2秒 | 返回非零，清理已启动服务器 | 返回1、端口关闭，通过 |

三项都是辅助脚本测试，**不是三项页面业务测试**。模拟页中的取消必填缺陷和持续轮询场景只准备了输入，没有在浏览器中执行；不得据此给真实业务系统报缺陷。默认程序返回码不符、服务器未清理即判对应辅助测试失败。

复现时将上游 `with_server.py` 下载至本目录并核验来源指纹，再运行 `python3 test_helper.py`。`fixture_server.py`只监听127.0.0.1；测试前确认8765端口空闲，不停止其他服务。页面探索入口为 `recon.py`，仍需要具备浏览器运行权限的环境。无付费工具调用。
