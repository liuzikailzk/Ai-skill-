# 云端自动核验

用户要求：每天北京时间 08:00 自动检查，网页关闭后仍能运行；询问时提供报告，保留每个发布版本及同版本修订的完整副本。

## 已实现的仓库侧任务

`.github/workflows/skill-monitor.yml` 使用 GitHub Actions 托管机器，定时表达式为 `0 0 * * *`（UTC），并在 main 上的版本清单、文件快照或工具变化时触发；也支持 GitHub 界面手动运行。它不会创建或替换 ChatGPT 学习任务。

每次运行测试工具，然后核验完整文件和历史链。Git 树未变化且上一份校验有效时，只比较树标识并复用结果，避免反复读取正文。发现文件损坏会明确报告失败。

报告保存在独立的 `automation-reports` 分支：`latest.md` 为最新可读报告，`latest.json` 为机器记录，`history/<运行ID>-<尝试次数>.json` 保留每次运行结果。报告发布不修改 main 的 Skill 或触发递归检查。每个真实 Skill 修订的完整副本由 `registry/snapshots/` 与 Git 历史保存，不依赖短期 Actions 附件。

运行成功必须有云端报告或 Actions 运行记录佐证，仅推送 workflow 文件不代表定时任务已经运行。GitHub 的定时执行可能排队延迟，并依赖 Actions 启用及平台额度；公开仓库的定时任务也可能因长期无活动而停用。之后查询报告时同时检查时间，不能把过期报告当成今日检查。

## 仍未接通

目前无直接读取 ChatGPT 维护会话、已安装技能库或制作会话的连接。任务只能核验实际进入仓库的文件；不能发现一个尚未导出到仓库的 ChatGPT 更新，也不能修复维护端保存操作。

因此即使仓库文件全部通过校验，总体状态仍是 `blocked_source_connection`。工作流绿色只表示检查及报告任务执行完成，绝不能当作维护端更新成功。只有建立受支持的源文件读取与更新通道，并实测之后，才可扩展这部分能力。

真实 Skill 尚未导入时报告 `awaiting_real_skill_files`，历史快照数为零。不能把用户截图中的版本号填写进空清单，假装已有对应完整副本。

## 用户询问时如何报告

Codex 使用现有 Git 连接读取 `automation-reports` 远端分支（不要覆盖工作文件），给出最新检查时间、是否按时运行、各 Skill 版本/修订及完整副本数、文件校验结果、维护源连接状态、是否实际修复。读取失败或没有新记录时直接说明，不承诺助手会话本身一直运行。

GitHub Actions API 当前返回 Forbidden，运行验证可使用原有受支持 Git 通道读取云任务提交的报告。不要提取认证秘密，也不要替换平台认证。
