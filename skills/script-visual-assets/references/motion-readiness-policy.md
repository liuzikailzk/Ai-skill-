# 可动性测试与动态交付门禁
修订：MOTION-READINESS-20261024-01。依据2026-10-24用户对《借光》的明确裁决，即时生效；这是强制制作规则，不是已验证的生成技巧。

## 执行顺序
图像生成 → 实际看图 → 逐镜可动性测试 → 有缺陷则重画并重新检查 → 核对图与动态驱动词一致 → 交付可用素材和完整驱动词。检查不过，停止可用素材交付；不得让用户先花视频额度验证已知错误，不得依靠视频提示词逆转错误图片。

## 每镜必须填写的检查表
记录镜号、实际图片标识、模型/入口/输入模式、图片用途（首帧/尾帧/身份/空间/构图）、起始状态、预备发力、接触/变化、结束状态、检查结果与缺陷位置。不得只检查文字里有没有要求。

| 检查项 | 必须从图中核对 | 阻断条件 |
|---|---|---|
| 光源与反射 | 光源位置、开关/燃烧状态、受光面、投影方向、地面/水面反射与前后镜一致；环境光必须有独立依据 | 唯一灯灭后仍保留其暖光；入水前灯已灭；不可能的投影或光照跳变 |
| 支撑与发力 | 脚/手与地面或支点实际接触，重心位置可解释，躯干与四肢连接清楚，下一步有发力来源 | 以双脚悬空奔跑结果姿态作为地面起跑首帧；缺支点、脚底滑行、断肢或遮挡无法判断 |
| 动作状态 | 起始条件尚未被消耗；动作有准备→接触→结果的顺序 | 用已断的绳表现“从完整到切断”；用已入水的灯表现“落水”；把结果图冒充首帧 |
| 道具/空间 | 唯一物件的持有、投出、落点、消失状态与下一镜一致，轴线/出口方向不跳变 | 已投刀后手中重新出现刀；人物无动作依据换位 |
| 输入可执行性 | 模式实际支持所提供素材；图片数量、顺序、用途与提示词对应 | 用户需要自行猜裁图方式、猜图片角色、猜首尾状态；拼图当首帧导致整板一起运动 |

腾空并非一律错误：真实跳跃中间帧必须有已建立的起跳与落点，可作中间/尾部参考；未经明确设定的“空中起跑”不得因画面好看而放行。不能用排除词遮掩实际图中相反的证据。

## 不合格就重画
光影断层、起始姿态无支撑、动作状态已发生或道具状态冲突，均先修图/重画，再重新看图并检查相邻镜。不能只加“灯应当亮”“双手为空”“不要漂浮”便宣告修好。重画方案本身不等于通过。仍不合格时报告制作阻塞，不交带病的“可直接生成”素材包。用户明确停止本次制作后，只归档，不再生成补救。

## 一起交付
每次动态分镜必须同时提供：
1. 已通过设计预检的图片素材。需要多张独立图片时，由助手准备并按用途编号，不让用户自行裁图猜顺序；仅在已核实入口支持且本任务适用时提供分镜板参考模式。
2. 对应该模型/入口/输入模式的完整动态驱动提示词，逐镜带起止秒数、景别、运镜、主体动作阶段、图像用途与衔接状态。静态生图词不替代视频词。
3. 多图输入的上传顺序、每张图的角色、各段使用范围及衔接关系；文本编号与实际素材一一对应。
4. 聊天正文里的完整可复制代码块，以及同份备份。修改后给完整新版，不能只给链接、差异片段或一张分镜板。

## 证据边界与后续验收
可动性测试是图像到动作的设计预检，不能保证视频模型执行。只完成看图检查时写“设计预检通过，视频效果未验证”；只有实际运行并检查视频后才记录视频实测。未经授权不增加付费调用；周考核一次视频生成的既定限制继续执行，失败不得重抽样改写结果。
实测先查人物/空间/物件连续性，再查光影和发力，再评叙事、美感。阻断项失败时整包不能用美术分数抵消，不以检查清单填完宣布通过。
