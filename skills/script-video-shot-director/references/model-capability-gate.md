# 视频模型核验与提示词适配：强制制作门禁

修订：MODEL-CAPABILITY-GATE-20261019-01。依据用户2026-10-19 23:15:11（Asia/Shanghai）明确指令：漫画分镜、剧本分镜都必须先确认画风、风格、宽高比和对标，查清目标模型的优缺点及最新版本支持的时长，再据此写提示词；中途换模型必须重新检索。这是用户指定的制作控制规则，不是可选建议，不授予新方法效果票。

## 1. 执行顺序与适用范围

正式制作必须依次通过：**理解当前素材与范围 → 风格约束卡确认 → 当前模型实际检索与能力核验 → 按能力安排生成片段、镜头和动作 → 交付适配提示词**。理解素材和检索可并行推进，但前两项与模型核验均完成后，才能交正式制作内容。

- 风格约束卡至少明确：媒介、具体画风或摄影方向、整体基调、准确宽高比、对标出处/实际查看范围/采用特征。已确认或明确授权决定的内容直接沿用；只补问影响结果的缺口，每次一问，不让用户重复提醒。
- 首次为本项目使用某模型时，必须主动联网检索并实际阅读当前官方资料；不能用记忆、旧模板、品牌印象、搜索摘要或用户一句“最新版”代替。不等用户再次要求“先查模型”。
- 门禁适用于新写及修改可直接提交视频模型的分镜、视频提示词、生成方案和复现试写；“先给一版”“只要提示词”“照旧”及仅改措辞不自动豁免。
- 仅启用/读取Skill、版本查询、原作理解、问题诊断、规则维护及未面向具体模型的剧情讨论，不因此自动检索或启动制作。漫画读图仍先还原格序、身份和对白；不因本门禁新增漫画页或图片。

## 2. 先确定查的是哪一个模型

记录完整目标：**厂商/模型系列＋准确版本或模型ID＋实际平台/软件/API入口＋版本档位＋本次输入模式**。标准版、快速版、预览版、托管入口和公司封装软件不能默认相同。昵称、产品名或“公司自己的Seedance”不足以证明底层版本和功能。

同时核对“厂商目前公开的最新版本”与“用户当前入口实际可用/选中的版本”，区分正式开放、预览、候补与预告。发现更新要说明差异，不能擅自切换模型，也不能把厂商最新版本能力套给旧入口。版本或入口不明时，先完成能够独立查证的部分，再只问一个最关键的缺口；界面、设置或平台文档可作入口证据，不索取密钥。

## 3. 查证来源与完整能力表

先查当前官方模型说明、帮助中心、API文档、更新日志与正式公告，并实际打开相关条目。按事实分别附出处，记录页面发布/更新日期（未知就标未知）、实际查看范围及本次核对时间（北京时间）。第三方托管入口同时查该平台的一手说明；宣传页、开发者文档、入口界面冲突时保留冲突并确认本次实际可选设置，不能挑较大的数字。

在项目中建立“模型能力核验卡”，以下维度逐项记录**支持/受限/不支持/未知、适用版本/模式、依据和本次影响**；不适用项写原因，不能空着跳过：

| 维度 | 必须核对的内容 |
|---|---|
| 版本与开放状态 | 当前最新公开版本、选中版本、档位与入口、相关发布日期、实际可用性 |
| 时长 | 本模式单次生成最短/最长及可选档位或步长；时长是否固定；参考/音频等条件是否改变上限；续写次数/累计时长若适用则另列 |
| 输入方式与参考 | 文生、图生、首尾帧、分镜图、多图、视频或音频参考的支持情况；图片/视频/音频数量、尺寸、长度及用途限制 |
| 画幅与输出设置 | 可选宽高比、分辨率、帧率及条件限制；模型设置与提示词中的文字要求分开 |
| 风格与身份 | 二维/真人等本项目媒介的适应情况，线条/材质漂移、脸/服装/道具一致性、角色引用与锁定功能的已知能力和边界 |
| 动作与空间 | 复杂交手、闪避、腾挪、接触受力、遮挡、多人站位和跨镜连续性的已知表现、失败条件及未知项 |
| 导演控制 | 机位、运镜、景别变化、多镜头与剪辑、时间指令和动作顺序的支持情况；不把自然语言意图当精确控制功能 |
| 声音与文字 | 原生音频、对白语言/口型、音效/配乐、字幕及画面内文字的能力、条件和限制 |
| 提示词与接口 | 官方建议的描述方式、长度限制、负面输入、参考调用、参数与语法；没有依据不编@标记、权重或接口字段 |
| 本次适用优缺点 | 汇总可利用的强项、已知短板、实测失败及未核实风险；版本/入口/权限等与本次相关的使用限制另列 |

区分官方能力事实、官方效果宣称、同版本原作者/本项目实测、以及推测。优缺点不能只抄宣传：除官方限制外，查看与本任务相关的一手测试/失败记录（有可访问证据时）；查不到就说明覆盖缺口，不伪造缺点、成功率或“已经掌握全部优缺点”。旧版结论只能作为待复查线索。资料阅读不等于生成实测，用户此前一个失败片段也不能证明整个模型都做不到。

## 4. 时长必须查清，再安排内容

单次生成上限、续写后的累计时长和后期剪辑成片时长分别记录。不得把广告片总长、演示视频长度或多个片段拼接长度当作单次生成能力；同系列不同版本/平台/模式不能共用一个上限。用户说“做15秒/30秒”只是成片目标，不是模型支持证据。

将目标成片时长与当前输入模式的真实可选时长对照：支持则在实际设置选择并写清；超限则按有叙事依据的切点拆成多个可生成片段，分别分配独立输入与衔接状态；不能靠提示词强求超限输出。单次片段内可以包含多个视频镜头，仍逐镜给起止秒数，另标片段本地时间与成片位置（需要时），不能混淆生成片段和漫画格。

**最大时长是容量上限，不是每段必须填满的目标。** 根据可见事件、对白语速、动作阶段和本项目节奏选择时长与镜头数，不为凑满时长拉长跑动、慢动作、对视或停顿，也不把复杂动作硬挤进不可能的时间。无依据不规定某模型“固定只能几镜/几动作”；节奏安排标为设计判断，模型时长与逐帧执行能力分别说明。

## 5. 检索结论必须落实到提示词

正式交付前，简明说明“**已核实能力/短板 → 本次具体处理**”，至少覆盖本次时长、输入方式、关键动作/一致性和所用参考/语法。不允许查完模型后照贴通用旧词，或只把另一模型的名字替换掉。

- 依据已核实的时长档位、参考用途、可用控制和已知限制，安排生成片段、镜头、动作密度、角色与空间衔接，以及声音/文字的生成或后期分工。
- 模型未支持的语法、参数、控制方式不得写成可用功能；关键能力未知时不依赖它设计正式方案。可改用已核实的输入方式或说明需要的验证，不把候选方法说成有效解法。
- 保留原作/剧本核心事件、身份、能力、对白和结果。为适应模型需要改变这些内容时，须先按既有忠实度规则取得相应授权；拆镜不等于改剧情。
- 风格、比例和必要约束必须经实际文字、参考或设置传给模型。已确认的场景空间和人物身份连续性优先，不能以保一致为由固定平视或让人物表情始终相同。

## 6. 换模型必须从头重新检索

发生下列任一情况，立即将原核验卡对当前生成任务标为失效，并暂停沿用旧提示词：**更换模型系列、版本/模型ID、档位、实际入口/平台，或输入模式发生会影响能力/时长的改变**。包括同品牌升级、从官网转公司软件、文生转图生/参考生，以及换回之前用过的模型；均重新执行第2–5节，不凭旧卡跳过检索。

重新查证新目标的当前版本/入口、完整能力维度、时长和相关限制，给出新旧差异及本次分镜/提示词需要调整之处。可以复用已确认的剧情、画风、宽高比和对标，但须核对新模型支持；不重复问无变化的创作问题。已经检索过同一天的新模型也不能因此免掉本次切换核验。

同一目标、入口和模式在同一项目/当前会话/同一北京时间日期连续制作，且资料可回读、没有更新信号或关键新需求时，可引用同一核验卡，逐次检查适用性。跨会话、跨日、发现更新/资料冲突或新增未覆盖能力需求时，重新检索核验；旧文档中“30天复审”等通用期限不替代这里的制作时效要求。

## 7. 缺证据就停止正式交付

没有实际检索、版本/入口/输入模式未确定、关键时长未证实、核心能力存在未解决冲突或风格卡关键项缺失时，**不得交可直接生成的正式分镜/提示词，也不得先套旧模板再补查**。检索不可用或资料无法打开，明确写“模型核验未完成”，给出已查部分、具体缺口和一个最关键的补充问题；可以继续独立的原作/剧本理解与问题分析。

用户提供的当前入口设置或正式文档可补足入口证据；不能把“不知道”包装成保守默认数值，也不能把用户随口估计当官方规格。次要且本次不依赖的未知项可标未知并绕开，不要求无关功能全部实测后才工作；本次必需能力与时长必须有依据。禁止声称已查、已读或已测试实际没有执行的部分。

## 8. 用户可见记录与发出前自检

首次使用或重新核验后，在正式提示词前交简明核验摘要：**核对时间｜模型/版本/入口/模式｜最新版本与当前所选差异｜单次可选时长及本次设置｜本次可用强项/限制/未知｜据此采用的处理｜来源**。完整能力表留在项目记录；每次正式交付注明本次依据的核验卡及适配结论，不能只说“已了解模型”。切换时补充新旧变化。

发出前逐项检查：
1. 画风/风格、准确宽高比、具体对标及当前范围是否明确并已确认/授权？
2. 是否实际检索并读取了当前目标版本和入口的一手资料，留有时间与来源？
3. 完整能力维度、强项、短板及证据边界是否逐项有记录？
4. 当前模式单次时长是否已证实，成片总长/续写时长是否分开？
5. 分镜时长、动作负荷、参考和提示词语法是否确实据能力调整？
6. 是否发生任何切换/过期/冲突触发，已经重新核验？
7. 是否把必要设置和约束实际交给模型，而非只留在内部？

任何必需项未通过，先补核验再发。只读了本规则不等于完成模型检索。项目模型核验属于用户指定的创作前置，按真实查询留痕；不冒充每日技巧学习/AI资讯扫描，不改其固定3次技巧＋1次资讯预算，不授候选票、不自动加分。
