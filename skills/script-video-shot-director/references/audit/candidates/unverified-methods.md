# 输入方式、风格与生成诊断

## 按输入方式分配信息

- 文生视频：补足主体外观、环境、初始空间、动作、镜头与画面风格；每镜一个主要事件。
- 图生视频：先读首帧已确定的构图、光照、角色与姿态，主要描述如何运动、相机如何变化以及结束状态；不要重复堆写静态信息或要求与首帧冲突的起始站位。
- 参考生视频：识别每份参考的用途（身份、服装、场景、风格、运动）；不要把参考图默认当首帧。多角色时明确对应关系，文本负责本镜站位、事件和运动。
- 分镜图参考：明确每张承担身份／场景／风格还是某时刻的关键状态；说明这些状态属于同一连续动作还是独立镜头。对接触、推动、交接等易跳变动作，可用“起始状态→接触与变化→结束状态”串联，逐段写清谁触碰谁、物件由谁支撑或持有、向哪移动、何时停止或松开；不机械增加镜头或多组生成。保持剧本已确认事件与结果。图片编号只标引用，不自动构成时间约束；文本仍须连接状态，上传顺序和文字指定不能保证精确执行。避免把边框、气泡和整页排版生成进视频；仅在入口支持时使用其引用方式。
- 不确定模型版本或入口能力时，只问影响制作的关键问题；涉及最新能力、长度与语法时核查官方资料，不把某模型技巧宣传成通用保证。

采用上述状态参考前，先检查图中接触点、左右方向、物件归属及固定空间是否自洽，再确认实际入口是多图参考、单首帧还是首尾帧。多图参考不要冒充多个强制关键帧；入口只支持首尾帧时，无法同时承担相同的中间状态参考测试。出现提前移动、穿透、复制道具、松手后跟手走或幻灯片式转场时，先定位参考冲突、动作省略或入口不匹配，再修改对应部分；没有视频实跑不宣称改法更优。

核查快照（2026-10-13，能力事实与方法效果分开）：ByteDance 于2026-07-31发布 Seedance 2.5，官方入口说明为即梦网页→视频生成→选择2.5，并给出按素材指定场景、角色等用途的多模态参考案例。2.0亦有多图参考能力。账号开放情况、输入引用标签与模式仍以当前界面为准；不把API字段直接贴进网页提示词。上述状态衔接是结合既有动作因果形成的待实跑策略，不是官方保证。来源：https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5 与 https://seed.bytedance.com/en/blog/seedance-2-0-official-launch 。本次读到正文及文字示例，未观看嵌入演示视频。

## 全片风格与每镜调度

沿用用户确认的参考，按“全片美术体系→场景光源与色调→本镜构图、动作和声音”分层；统一不等于每场都阴暗、逆光或暖光。收到网络风格模板时先识别为学习材料，筛选方法，不直接把模板中的夜景、都市、禁字幕、无BGM或器材组合设为项目要求。用户明确采用的条件才执行。

- **全片美术**：固定真人／二维／三维、线条上色、材质表现、饱和度和影调倾向。把“电影感、某相机色彩”转成可见目标，器材／胶片名称只作辅助线索；数字摄影与胶片模拟可以组合，但要明确主导风格，不能据名称承诺精确复刻或风格硬锁。“8K”不是输出设置；“暗部保留10%”缺少测量定义，不当作精确控制参数，可改为“背光面较暗，仍辨清轮廓和必要纹理”。
- **场景照明**：交代主光从哪里来、照向哪里、冷暖主次与阴影软硬。冷环境与暖灯光可共存，需说明区域；柔光通常对应较柔的阴影过渡，硬阴影应有相符的光源或明确的局部／第二光源依据。优先描述一个占主导的照明方向，允许合理的环境反射；“无额外补光”不等于抹去自然反射或要求多种灯光同时都为唯一光源。不要无依据添面部轮廓光。限制非光源表面的过曝并保留关键细节，不要求所有发光点都显示表面纹理。
- **材质与细节**：按已锁定资产、材料工艺、新旧程度和景别选择可见细节，避免所有衣服都起球、木材都显年轮、金属都氧化、皮肤都布满细纹。真实不等于全部漫反射或没有高光；保留金属反射、玻璃透光等差别，克制统一塑料亮膜。颗粒／数字噪点是成像质感，空气浮尘是场景内容，色散／暗角是光学或后期效果，不能混成写实必选包；只有情境和已确认风格需要时才添加。
- **景别与焦点**：先说明人物在画面占比、要看清的对象、焦点和空间关系，焦段仅为辅助，不能固定“85mm＝全景、135mm＝特写”。景别还与机位距离和画幅有关，景深同时受光圈、焦距及对焦距离等影响；远处物体不必一律模糊，动作接触点、证据和关键环境不能被无条件虚化遮掉。
- **镜头与运动**：每镜保留明确的主要调度，不把“不要乱切”扩大为整片禁切。固定机位与手持漂移二选一或明确切换；手持呼吸感仅在当前镜头需要时采用，幅度克制，避免遮住动作。ACT、hit stop、震动按既有动作规则绑定具体事件；惯性表现为启动、制动、收势及衣物跟随的自然先后，不把全身普遍延迟或拖影写成动作流畅。

### 声音与交付约束

声音先区分对白／OS／旁白、动作音效、环境底声和配乐，保留原作文字与已确认交付要求。需要有声而无配乐时，写清“保留对白、必要音效和环境音，不加配乐”，避免“只能环境音”误排除对白；禁字幕不等于禁人物说话，也不自动删除剧情招牌、短信或技能文字，按当前项目对这些类别的要求分别处理。

需要空间声音时，将“[场景专属混响]、[声像定位]”换成已知空间与事件中的具体描述：声源相对画面的位置、远近、遮挡、接触同步及合适的余响；环境音为台词让出清晰度，不用大混响代替空间感。不凭空新增鸣笛、雨声等改变场景的声音。目标模型不支持音频时明确留作后期要求，不保证文字生成精确声像。

全局约束按既有输出偏好集中管理，不逐镜机械重复。用户要求可独立提交的完整提示词时，每个实际生成输入保留必要的已确认约束一次，不能假定外部视频模型知道聊天中的约定。空白的“场景为”及方括号占位符须用已知信息填实；缺口影响制作时只问关键问题，纯学习时无需虚构场景。

影视适配：沿用剧本的场次、台词和交付格式；这些检查帮助落实摄影设计，不引入漫画读格、技能大字默认规则或新的互动分支。

## 格式与信息优先级

不存在已验证对所有模型最优的统一格式。以“主体与空间→主要动作及结果→镜头响应→必要声音／表演→局部风格变化”为可选组织顺序，省去参考已经表达且无需改变的细节。

时间轴用于表达先后和重音，不能承诺模型逐秒照做。不要每半秒堆多个运镜或复杂动作。分镜图与首尾帧方案是可选控制手段，需符合当前工具实际能力，不要求用户为每段都重建流程。

## 成片无力时的诊断顺序

1. 对照输入资产与成片，定位失败发生在发力、接触、受力、镜头、声音还是揭示节奏。
2. 优先检查动作是否可执行、参考是否冲突、单镜事件是否过多，再修改对应指令。
3. 在用户要求生成验证且可用时，用相同参考和生成设置做少量对照，一次只改一个主要因素。没有实际生成就不能宣称验证有效。
4. 提示词仍不稳定时，按失败点考虑独立短镜、关键帧／动作参考，或剪辑中的节奏、短震、音效处理；不要一律归咎于“参考生视频不行”。
