# 制作正文｜按需读取

从提交 29db0351359ce947861264bc441e759bc0376916 的现有制作正文提取，未新增技巧或验证票。当前入口中的交付、模型核验与媒介边界优先；忽略正文内要求跨层加载其他文件的指令。相关文件须由任务入口一次选定，读取到第1层即停止。

## 专用范围与分流

本 skill 专门处理漫画素材及其动态化：以页面、漫画格、气泡、画面符号和相邻格为证据。纯影视剧本文本优先交给 `script-video-shot-director`，不要要求剧本用户确认漫画阅读方向或气泡归属。

混合素材时，先分别理解漫画和剧本，再以用户确定的主依据组织分镜；冲突影响剧情时只问关键问题，不擅自以一种素材覆盖另一种。

## 通用知识审计与媒介边界

用户授权维护两套分镜Skill，不等于提前给每个候选人类票。新方法先进入候选区，完成证据、复现和周五人类审查后，才按对应媒介发布；不得将未验证方法直接写成现行“可选策略”。静态资产、影视场次、漫画读格分别维护；通用规则可以共用证据，但适用性和复现结果须分别说明。保持项目已确认的角色、画风、台词、剧情及进度，不继承别的项目设定。

## 目标

把漫画当作“剧情证据＋视觉关键帧”，而不是一组待描述的静态图片。先还原阅读顺序、人物身份、时间空间和事件因果；经用户确认后，再生成能够连续运动的动态视频分镜。

始终采用两阶段流程：

1. 漫画理解与确认。
2. 动态分镜生成。

不得在关键顺序、人物身份或对白归属尚未确认时直接跳到第二阶段。已经确认的片段直接继续生成或修改，不重复要求确认；仅诊断提示词或学习参考视频时，不强行启动漫画识别流程。

采用“一套基础规则＋按镜头切换日常、悬念、打斗模块”。同一片段允许切换模块，不把打斗用语强加给全片。用户当前指示优先于旧项目格式；先识别问题，再选表现手段。

## 开始新项目

为每部漫画建立独立项目记忆档案。若用户已经提供档案，先完整读取；若没有，按 [project-memory.md](project-memory.md) 建立。

仅确认当前缺失且会改变结果的项目参数：

- 漫画或项目名称；
- 真人化、动画化或保留漫画质感；
- 画面比例；
- 视频模型及输入方式：参考生、图生、文生或分镜图参考；
- 角色与场景参考图；
- 需要处理的页数、章节或范围。

每次只问一个最关键的问题。已经确认的参数写入项目档案，同一项目后续自动沿用；切换新漫画时不得继承上一项目的视觉风格、人物设定或剧情判断。

## 第一阶段：漫画理解与确认

### 1. 确定观看顺序

先判断图片顺序、页面方向和漫画格阅读顺序。检查横排、竖排、从左向右、从右向左、跨页大格、长条格、嵌套格、破格、回忆插格和同场景反应分格。

若顺序明确，只简短说明；若存在两种以上合理顺序，指出具体图片和格子位置，并向用户提问，不得自行选择。

详细判断规则见 [panel-reasoning.md](panel-reasoning.md)。

### 2. 还原本批剧情

按阅读顺序内部逐格分析：

- 场景、时间和现实层级；
- 出场人物、站位、视线和关系；
- 动作起点、结果及格间缺失过程；
- 对白、旁白、内心独白、拟声词及归属；
- 表情、构图、景别和叙事重点；
- 回忆、想象、梦境、Q版反应和现实动作的区别。

对用户只展示连贯的剧情还原，不逐格汇报全部推理。只有出现歧义时，才展开对应漫画格及判断依据。

### 3. 建立阶梯记忆

姓名未知时，为重要人物建立稳定临时代号和视觉锚点，例如“角色A｜黑发男青年｜持手机”。不要依赖作品外部知识擅自填写真名。

持续累积人物的外貌、服装、道具、说话方式、关系、出场时间和年龄阶段。区分“幼年、少年、成年、回忆阶段”等版本，不因外形变化自动拆成不同人物，也不因相似就强行认定为同一人。

采用双轨记录：

- 阅读轨迹保留“当时身份未知”的状态，避免后见信息污染推理；
- 当前档案保存最新确认身份，供后续分镜统一使用。

新证据出现时，更新映射与可信度并保留修正记录，不要静默覆盖旧判断。只有用户确认本批理解正确后，才把内容写入“已确认事实”；未确认内容只能进入“暂定推测”。

### 4. 主动提问

遇到以下情况时暂停并一次只问一个问题：

- 重要陌生人物的身份影响剧情；
- 疑似同一人物的跨年龄或跨造型版本；
- 对白气泡的说话人无法确定；
- 现实、回忆、想象或梦境无法区分；
- 观看顺序存在多种合理解释；
- 补全内容会改变人物动机、关系、因果或结果；
- 漫画文字模糊且无法可靠识别。

问题必须精确定位图片和格子，描述人物视觉特征，并尽量给出互斥选项。普通路人、群众和不影响当前分镜的一次性角色可先使用临时代号，不要频繁打断用户。

### 5. 第一阶段输出

默认只输出：

1. 观看顺序；
2. 本批剧情还原；
3. 本批记忆变化；
4. 若仍有关键疑点，提出一个问题；没有疑点时不虚构问题。

用户确认无误后，更新项目记忆档案并进入第二阶段。若用户只要求理解漫画，不生成分镜，则停在第一阶段。

## 第二阶段：动态分镜生成

### 1. 划分叙事单元

不要机械执行“一格漫画＝一个分镜”。先判断时间、空间、因果和叙事功能，再划分完整叙事单元。

同一整体画面内的多个小格，只要属于同一场景、同一时刻或同一反应链，默认写成一个分镜。长条格、大型场景格、人物与环境合并格也优先作为一个完整分镜。只有场景、时间、现实层级或核心事件明显改变时才必须拆分。

合并服务于连贯性，拆分服务于信息揭示和动作可读性。每镜保留一个主要视觉任务和可执行的动作链；不要机械碎切，也不要把多个独立攻防回合塞进一镜。

### 2. 克制补全动态过程

允许补充漫画格之间必需的动作过程、自然反应、视线移动、重心变化、停顿、环境反馈、人物入画方式和镜头衔接。

也可根据现场关系补充当前人物的中性反应。例如男主被反派打倒后，可补反派收回手臂、低头观察或向前半步，以建立位置和压迫关系。

补充内容的依据优先级：

1. 当前漫画画面；
2. 前后相邻格；
3. 已确认的角色记忆；
4. 当前场景空间与情绪；
5. 通用影视表现。

默认不得新增原作没有表达的新剧情、新对白、新人物、新道具、关系变化、动机或结果。用户已经授权的情绪强化、构图调整和动作逻辑修补直接执行；不得借此更改胜负、能力设定或重要事件。证据不足时使用最小、中性的补充；若仍可能改变含义，先提问。

### 3. 保留原作构图与文字

以漫画的叙事重点、人物关系和关键视觉信息为锚点。用户允许改编时，可调整景别、构图、揭示顺序和攻防衔接，以适应动画张力；旧漫画缺失发力、接触或反应过程时，补足动作因果，不能把不连贯的姿势直接串起来。保留核心事件与结果。

对白默认原文锁定：未经授权不得润色、缩写、扩写、合并、重排或添加。用户明确指定的台词、说话人、OS转喊话等改动优先；只修正用户确认的识别错误。模糊文字或说话人不明时先提问。

旁白与内心独白保留原文，但要放在自然的转场、停顿、视线或回忆节点。拟声词不作为人物台词，转换为对应的声音、动作和物理反馈。不要让旁白、独白和强动作同时争夺画面节奏。

### 4. 设计张力、动作与声音

生成前读取 [direction-and-action.md](direction-and-action.md)，按镜头选择日常、悬念或打斗规则。把张力落实为信息隐藏与揭示、构图大小关系、表演递进、快慢与动静对照；不能只写“压迫感、热血、力量感拉满”。

打斗先建立“发力／攻击方向→接触或闪避→受力反馈→重心恢复与下一动作”。再把跟镜、顿挫、震动和自然声音绑定到具体事件。ACT可作动作游戏表现的引导词，不保证模型执行；没有接触的威慑或嘶吼不得套用受击反馈。

逐句区分对白、内心OS、旁白、技能名、拟声词和说明文字。为对白指定有依据的语气、重音、停顿及可见表演，OS不做开口喊话。默认只有实际释放技能时出现技能名文字特效；普通对白、OS、敌人名字与惊叹句不做强调字幕。用户另有字幕要求时从其要求。技能字体按角色个性与能力材质区分，同一角色保持一致，不能遮挡接触点或表情。

### 5. 适配输入与生成最终提示词

读取 [input-and-style.md](../../../knowledge/shared/input-and-style.md)，分清参考资产承担的身份、构图、画风或运动作用；将全片基调与光影规则和每镜动作调度分开管理。不要保证文字能硬锁定风格或精确帧数。

按 [output-format.md](output-format.md) 选择用户当前需要的格式。默认直接在对话交付可复制文字，用户不要求时不生成下载文件。分析、依据和制作建议放在可复制提示词之外。

## 输出前自检

逐项确认：

1. 阅读顺序是否有明确依据；
2. 人物身份是否来自当前漫画、项目档案或用户确认；
3. 是否保留了未知身份和跨年龄映射的修正轨迹；
4. 是否只把用户确认内容写入已确认记忆；
5. 是否错误地把回忆、想象、Q版或拟声词当成现实动作或对白；
6. 是否机械地一格拆一个分镜；
7. 补全动作是否克制且未改变剧情；
8. 原对白是否逐字保持且归属正确；
9. 构图调整是否仍保留漫画叙事重点；
10. 最终格式是否符合用户最新要求、便于直接复制；
11. 每镜是否有明确视觉任务，张力是否由可见行为与节奏实现；
12. 打斗是否有接触／闪避因果、方向一致的反馈和连续站位；
13. 镜头震动、顿挫和声音是否绑定事件，而非全程平均铺满；
14. 是否正确区分OS、对白、技能名与敌人名字，语气和文字特效是否用在重点；
15. 全片风格是否兼容日常与打斗，参考图内容是否和动作要求冲突；
16. 是否把创作者经验、模型能力与实际验证结果区分开，未声称未看过或未测试的效果。
